# Custom I18n

Hearth GPUI includes translations for its components. Applications can add a language or override individual translations without copying the complete built-in locale files.

This feature requires `rust-i18n` 4.2 or later.

## Add the dependency

Add `rust-i18n` to the application crate that owns your locale files:

```toml
[dependencies]
hearth-gpui = "0.5"
rust-i18n = "4.2"
```

## Create an application locale file

Create `locales/ui.yml` in your application crate. Put component translations under the `hearth_gpui` namespace:

```yaml
_version: 2
hearth_gpui:
  Calendar:
    week.0:
      fr: Di
    month.January:
      fr: Janvier
  DatePicker:
    placeholder:
      fr: Sélectionner une date
```

The namespace must be `hearth_gpui`, matching the Rust crate name `hearth-gpui` with hyphens converted to underscores. Translation keys can be found in [Hearth GPUI's built-in locale file](https://github.com/JonZhang3/hearth-gpui/blob/main/crates/ui/locales/ui.yml).

## Register the extension

Initialize the application's locales at the crate root:

```rust
rust_i18n::i18n!("locales", fallback = "en");
```

Register them before initializing Hearth GPUI:

```rust
app.run(move |cx| {
    rust_i18n::extend!(hearth_gpui);
    hearth_gpui::init(cx);

    // Open windows and initialize the rest of the application.
});
```

Call `extend!` only once during application startup.

## Lookup priority

The application's translations take priority over the component's built-in translations:

```text
Application locales (locales/ui.yml)
             │
             │ key not found
             ▼
Hearth GPUI built-in locales
```

This deep-merge behavior means that:

- A new locale, such as `fr`, can contain only the keys your application needs.
- A translation with the same locale and key overrides the built-in value.
- Keys not supplied by the application continue to use the built-in value.
- Future Hearth GPUI translations remain available without being copied into the application.

For example, defining only `hearth_gpui.Calendar.month.January.en` changes January's English label while all other English calendar labels still come from Hearth GPUI.

## Select a locale

Use rust-i18n to change the active locale:

```rust
rust_i18n::set_locale("fr");
```

Components will then resolve their translated labels using the selected locale and the priority described above.
